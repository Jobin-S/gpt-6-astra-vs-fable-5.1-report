On a subscription you pay a fixed monthly price and use the model until you reach the plan's usage limits. You never see a per-task bill. To compare the two models fairly, each run's token usage is converted into what it would cost on the API, where developers pay for every token.

API pricing is quoted per million tokens, and a token is roughly ¾ of an English word. Each model has its own rates, and every request is billed in three parts:

  1. 1
    Input tokens. Everything sent to the model: your prompt, files, screenshots, tool results and the conversation so far.
  2. 2
    Cached input tokens. Input the provider has already seen recently, such as the same long conversation sent again. Cache reads are billed at a small fraction of the normal input rate.
  3. 3
    Output tokens. Everything the model writes: code, answers, tool calls and reasoning. Output is the most expensive part per token.
// cost of one run
cost = input × input_rate
     + cached × cached_rate
     + output × output_rate  // rates are per 1M tokens

Agents work in loops. Each step sends the whole conversation back to the model, so a long task can process tens of millions of tokens, most of them cached. That is how Astra processed 35.75M tokens for $7.75 in the real estate task while Fable used 5.98M tokens for $60.76. The total token count tells you little until you know how much was cached and what each model charges.

External tools are billed separately. In Round 2 the video was generated with Higgsfield credits (1 credit = ₹4.95). That cost is listed on its own and is not part of the LLM cost.
